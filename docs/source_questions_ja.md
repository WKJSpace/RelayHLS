# RelayHLS のソースコードに関するご質問への回答案

対象は公開リポジトリのコミット
`3b8b7ffc943b19626f38cafa517949304a488067` です。
実装の動作を維持するため、整理では未参照の定数表だけを削除し、
デコーダ本体、使用中の表、設定、入出力形式および既存の結果は変更していません。
詳細は [生成方法の説明](graph_generation.md) をご参照ください。

## 1. 接続されていない故障候補について

ご指摘のとおり、次数が 0 の列が存在します。
公開版の行列は合成用の人工的な疎行列で、9,000 は列・記憶領域の
スロット数です。実回路から抽出した故障機構の数を表すものではありません。
1,008 行に各 8 本の辺を配置するため、辺数は 8,064 です。

| 構成 | 接続のある列 | 次数 0 の列 |
| --- | ---: | ---: |
| C8/V16 | 7,961 | 1,039 |
| C16/V16 | 7,349 | 1,651 |
| C16/V32 | 7,349 | 1,651 |

既存実装では、`vnu_pass` が `H_COL_DEGREES[j] > 0` の列だけを更新します。
次数 0 の列には辺メッセージがなく、その硬判定ビットは 0 のままです。
候補コストも、接続のある列のみを列挙した `ACTIVE_FAULT_INDEX` から計算します。
一方、事前値・周辺値の記憶領域と入出力のサイズは 9,000 列分を維持しています。
今回の整理では列の削除、番号の変更、記憶領域の縮小は行っていません。

また、C8 と C16 は並列グループの制約が異なるため、同じ寸法でも接続関係は
同一ではありません。この点の説明を訂正しました。
実回路では「検出器に接続せず論理作用だけを持つ故障」もあり得るため、
次数 0 の列を一般に無害とみなすことはできません。
本人工行列の扱いは、そのような物理故障の復号性能を保証するものではありません。

## 2. 未参照の定数配列について

ご指摘の配列は、デコーダ本体と付属のスカラー参照テストベンチから
参照されていませんでした。用途は、隣接関係・バンク配置を別形式で表す
参照用の表、または未使用の仮置き表です。

- 4 種類の `EDGE_BANK_FOR_*` / `EDGE_ADDR_FOR_*` の代わりに、
  実装では `CNU_EDGE_*` / `VNU_EDGE_*` のスケジュール表を使用します。
- `H_COL_NEIGHBORS` および H の CSR 表は、現在の復号経路では使用しません。
  テストベンチで使用する隣接表・辺番号表は残しています。
- 事前値はパックされた入力から読み込みます。生成器の `PRIOR_INIT`、
  公開ヘッダの `PRIOR_LAMBDA` は未使用です。
- A の計算は `A_ROW_DEGREES` と `A_ROW_NEIGHBORS` を使用するため、
  `A_CSR_ROW_PTR` と `A_CSR_COL_IDX` は不要です。
- 収束確認は設定された全検出器を比較し、`CONVERGENCE_MASK` は使用しません。
- carry は `CARRY_DETECTOR_START + m` から抽出し、`CARRY_OUT_ROWS` は使用しません。

これらの未使用表は、ヘッダと両生成器の出力から省くことができます。
今回その整理を行いました。使用中の表の値、復号処理および設定は維持しています。
なお、外部のプログラムがこれらの未使用表を直接参照している場合は、
そのプログラム側で参照先を変更するか、整理前の版を使用する必要があります。

## 3. 定数配列の数値の決定方法について

H の行次数・列次数は、それぞれ各行・各列に接続された辺の数です。
辺番号は行と隣接スロットの順に付与し、隣接表と辺番号表はこの接続関係から作成します。

人工行列では、行 i、スロット s、辺番号 e に対して、故障列の探索開始位置を

```text
j0 = (1543 e + 17 i + 9973 s) mod NUM_FAULTS
```

とします。その位置から順に探索し、列次数の上限、同一行内の重複禁止、
バンクのポート数制約を満たす列を選びます。
これは再現可能な人工負荷を作るための規則であり、量子回路の物理モデルではありません。
実回路用の生成器は入力された検出器・故障の接続を使用します。

辺メモリのバンク番号は、現在のバンク占有数と優先順から貪欲に選択します。
各 CNU/VNU グループについて、同一バンクへのアクセスを 2 以下に制限します。
アドレスは、そのバンクに既に割り当てられた辺数です。
したがって、バンク番号は単純な「辺番号 mod バンク数」では決まりません。

ノードを P 個ずつ処理する場合、グループ番号は `floor(ノード番号 / P)`、
レーン番号は `ノード番号 mod P` です。
これらと隣接スロット・バンク・アドレスから `CNU_EDGE_*` / `VNU_EDGE_*` を作ります。
硬判定・事前値の循環バンク配置は `bank = j mod B`、`address = floor(j / B)` です。

加えて、現在の生成器には、公開ヘッダとの差分が既に存在することを確認しました。
事前値のパック幅、FIFO 深さなどを維持するため、今回ヘッダ全体の再生成は行っていません。
新しい行列を生成する場合は別ファイルへ出力し、これらの差分を確認してから置き換える必要があります。

## 整理後の確認

Supernova で全 3 構成を確認しました。各ヘッダに残した 84 個の定数宣言は
整理前とバイト単位で同一で、保護対象の実装・設定・結果ファイル 53 個も同一でした。
生成器・整理確認テストは計 81 件すべて成功しました。
各構成 32 ケース、計 96 ケースの段階処理・出力トレースは整理前後で同一でした。
最適化したネイティブ C++ のデコーダオブジェクトおよび確認用実行ファイルも同一でした。
この確認は既存動作の維持に関するもので、新規の HLS 合成・配置配線・実機計測ではありません。
